## Place a window

All defaults use **Ctrl + Alt** on Windows and Linux, or **Control + Option** on macOS. Digits are on the **number row**, not the numpad.

| Key with Ctrl + Alt | Position | Initial size |
| --- | --- | --- |
| 1 | Left half | 50% width, full height |
| 2 | Right half | 50% width, full height |
| 3 | Center | 50% width and height, centered on both axes |
| 4 | Bottom left | 50% width and height |
| 5 | Bottom half | Full width, 50% height |
| 6 | Bottom right | 50% width and height |
| 7 | Top left | 50% width and height |
| 8 | Top half | Full width, 50% height |
| 9 | Top right | 50% width and height |
| 0 | Fill work area | Full width and height |

Every placement targets the active window on its current monitor. A window spanning displays uses the display with the largest overlap; an off-screen window uses the nearest display. Application minimum sizes can limit the result.

## Resize and fill

| Shortcut | Action |
| --- | --- |
| Ctrl + Alt + - | Shrink current width by 25% |
| Ctrl + Alt + = | Expand current width by 25% |
| Ctrl + Alt + Shift + 8 | Fill the last saved gap with a different window |
| Ctrl + Alt + ↑ | Move the shared horizontal boundary up (Windows) |
| Ctrl + Alt + ↓ | Move the shared horizontal boundary down (Windows) |

Expansion uses the `=` / `+` key **without Shift**. Ctrl + Alt + Shift + = also expands unless assigned to another action. Gap filling uses Shift + 8 (`*` on the number row). Numpad keys can be recorded separately.

Read [Resize & refine](/tt-pane/resizing/) for anchoring, growth cycles, and neighboring-window behavior.

## Move focus — Windows, macOS, and GNOME Wayland

| Shortcut | Direction |
| --- | --- |
| Ctrl + Alt + H | Left |
| Ctrl + Alt + J | Down |
| Ctrl + Alt + K | Up |
| Ctrl + Alt + L | Right |

Outside centered groups, focus moves to the nearest window by center distance within a 90° cone, including across monitors. Ungrouped windows stay in place. Spatial navigation has no wraparound; focus stays put if there is no candidate. A grouped destination returns to its saved center.

**Include middle windows in H/J/K/L navigation** in Settings defaults to **Off**, including for existing configurations. Outside a centered group, regular H/J/K/L and CLI focus navigate background edge-snapped windows. Turn it On to include floating and centered windows. Inside a centered group, H/L always rotates through its members.

When middle-window navigation is enabled, **Settings → Advanced → Filter middle windows by visibility** optionally requires more than the **Minimum middle-window visibility** percentage of a middle window's frame to be on-screen and uncovered. The filter defaults to Off and the percentage to 10% (range 0–99%). This applies to spatial navigation, not H/L rotation inside a group or hold-to-enter. Edge snaps remain reachable when covered. Minimized, hidden, cloaked, and utility windows stay excluded. Advanced starts collapsed and also contains width and growth controls.

Tap **Ctrl+Alt+H/L** (release before **400 ms**) for regular navigation. Hold for **400 ms** from a background edge-snapped window to enter middle windows, including covered ones. From a centered member or floating middle window, hold to exit to background edge-snapped windows on the same monitor. Holds fire once; release before holding again. If no candidate qualifies, focus stays put. Remapped horizontal focus shortcuts work the same way. Holds require the running tray app.

Holds require Windows. macOS and GNOME shortcuts perform regular navigation on press; macOS targets the current Space and GNOME the active workspace.

## Centered groups — Windows and GNOME Wayland

Press **Ctrl + Alt + 3** on each window you want in a group. Windows must be on the same monitor and placed using Center; dragging them to the middle does not enroll them.

The focused member returns to its saved centered size and position, including growth. Inactive members shrink to the first Center snap size (half the work-area width and height), and stagger left/right and down by up to **25% of the focused window's width and height** per step. Spacing compresses to fit the work area. Circular enrollment order keeps both sides populated. Selecting a window outside the group preserves its current layout and main window size. The main window shrinks only when another centered member on the same monitor takes over; groups on other monitors keep their layout.

**Ctrl+Alt+H/L** rotates through centered members with wraparound, including covered windows. Repeated L continues cycling; a single-member group stays put on a tap. Hold H/L for **400 ms** to exit to background edge-snapped windows on the same monitor. **J/K** leaves for background windows above/below, preferring the leftmost column. Clicking or Alt+Tabbing to a member restores its saved size while the tray app runs.

Moving or resizing a member manually, another placement/width shortcut, changing monitors/work areas, minimizing, maximizing, hiding, or closing removes membership. Center explicitly rejoins the window. Repeated Center presses still grow the focused window and update its saved centered size. Groups are independent per monitor.

CLI Center/focus actions share the same saved groups. Mouse and Alt+Tab observation requires the running tray app. Hold-to-exit is Windows-only; use J/K to leave a group on GNOME.

## Change a shortcut

1. Open **Settings…** from the tray menu.
2. Click a shortcut and press your replacement combination.
3. Press **Escape** to cancel recording, or **Backspace** to disable that action.
4. Select **Save changes**.

Duplicate shortcuts are rejected. Native registration conflicts appear in Settings; failed registration preserves the previous bindings. On GNOME Wayland, saving re-registers the GNOME shortcuts. See [platform setup](/tt-pane/platforms/).

Older configurations gain missing focus actions unless a default key is already taken. Existing custom or disabled bindings are preserved. Older configurations may need the two boundary shortcuts recorded manually, or defaults reset and saved.

## Experimental tiling actions (Windows)

Available on `experimental/hypr-tiling`. Defaults follow Hyprland's Super+Shift convention on **Win + Shift**. Configurations that predate an action gain its default unless that key is already taken; actions already present (including previously migrated unbound entries) keep their binding. Reassign shortcuts in Settings or use `tt-pane apply ACTION` (also exposed in the Herdr manifest).

| Default | Action | Behavior |
| --- | --- | --- |
| Win + Shift + G | `toggle-tiling` | Enable/disable shared runtime tiling; enabling tiles existing eligible windows |
| Win + Shift + F | `toggle-float` | Remove the selected tile from the tree, or reinsert a floating window |
| Win + Shift + H / J / K / L | `swap-left`, `swap-down`, `swap-up`, `swap-right` | Swap with the nearest tile in that direction on the same monitor. With tiling off, trade places with the nearest window in that direction, on any monitor |
| Win + Shift + O | `toggle-split` | Toggle the immediate parent's direction; requires `preserve_split = true` |
| Win + Shift + E | `resize-mode` | Enter resize mode: H/J/K/L (or arrows) move the divider next to the focused tile in that direction, so H/L always change widths and J/K heights. Hold a key to keep moving. Press I to size only the focused window instead (H/L narrower/wider, K/J shorter/taller, keeping the edge nearest the screen edge); press I again to go back to shared edges. Esc, Enter, Win + Shift + E, any other shortcut or 10 seconds idle ends it. Shortcut only, not a CLI action |
| Unbound | `resize-left`, `resize-right` | Move the nearest vertical split boundary left/right by five percentage points (what H/L do in resize mode). With tiling off, they move the edge the focused window shares with its neighbors, resizing every window along it by 5% of the screen |
| Unbound | `size-narrower`, `size-wider`, `size-shorter`, `size-taller` | Resize only the focused window by 5% of the screen (what H/L/K/J do after I in resize mode). Neighbors don't move |
| Unbound | `split-grow`, `split-shrink` | Change the selected tile's share of its immediate parent by five percentage points (Ctrl + Alt + = / - do the same on tiled windows) |

Windows reserves Win + Shift + S, T, P, R, and X (so resize mode uses E), and Win + L always locks the PC, so Hyprland's exact Super bindings cannot be reused.

On tiled windows, H/J/K/L uses tree geometry (including deep tiles), then falls back to regular navigation (including other monitors) past the tree's edge; horizontal hold gestures also navigate tiles. `shrink-width`/`expand-width` act like `split-shrink`/`split-grow`, and `resize-up`/`resize-down` moves the nearest horizontal split boundary. Split grow/shrink and `-`/`=` act on the tile's immediate parent, whose direction depends on the tree; resize mode is the predictable way to pick an axis. A lone tile has no split to adjust. Ratios stay between 10% and 90%.

Snap/center/fill-gap actions float a tiled window before normal placement. Floating windows keep ordinary positioning behavior. `toggle-float` on a centered group member removes it from the group (the remaining members rearrange) and retiles it. Apps listed in `float_apps` must be removed from that list before retiling. All tiling actions other than `toggle-tiling` and swaps require active tiling (with tiling off, H/L in resize mode move a shared window edge and J/K move a shared boundary between stacked windows); GNOME skips registering them until its backend is implemented.

The runtime toggle persists in the shared sidecar. Saving Settings makes the saved toggle authoritative again. See [configuration](/tt-pane/configuration/#tiling-experimental-windows) for the full behavior.
